OPA Optics

A bookmarklet for the Okta Privileged Access console. Unofficial: not made or supported by Okta. It groups your servers on the home page, shows which security policy gives you access on each server page, and lists any user’s server access, with an export for access reviews.

Recommended: userscript manager

Runs automatically on every Okta Privileged Access page and updates itself when a new version is released.

  1. Install Violentmonkey (open source) or Tampermonkey.
  2. In your browser’s extensions page, open the extension’s Details and turn on Allow User Scripts (or turn on Developer mode if that option isn’t there).
  3. Install OPA Optics, then click Install when your userscript manager asks.

Or: bookmarklet

No extension needed, but you click it each time you open the console. Show your bookmarks bar (Ctrl+Shift+B, or Cmd+Shift+B on a Mac), then drag this button onto it.

Dragging is the install. Clicking the button on this page does nothing.

Can’t drag? Create the bookmark by hand
  1. Copy the bookmarklet code below.
  2. Add a new bookmark (right-click the bookmarks bar, then Add page).
  3. Name it OPA Optics and paste the code into the URL field.

Use

  1. Sign in to your console at https://{org}.pam.okta.com/t/{team}/.
  2. Click the OPA Optics bookmark. It keeps running as you move between pages in the console.
  3. Click it again after a full page reload, or after signing in again.
  • Home page: your servers appear in a list grouped by project, server type, name prefix, label or your access, with search. It opens automatically; untick Open automatically in the list if you’d rather open it with the Grouped servers button. Clicking a server opens its Accounts page.
  • Health tab (admins, in the same list): checks policies (inactive, matching no servers, nobody in their groups, servers no policy covers), server agents (not seen recently, behind the latest version in use) and admin roles, each with a CSV export.
  • Licence tab (admins): estimates resource units from users, servers, SaaS apps and Active Directory accounts, and compares them with the number bought. An estimate only, not a quote.
  • Server pages: a banner along the bottom of the page shows the policy rules that give you access to that server, what matched, through which of your groups, and any conditions such as an access request.
  • User pages: a panel lists the servers that user can reach, separating standing access from access that needs an approved request, with the policy, rule and group behind each. Export CSV downloads it for access reviews. The panel also lists the devices the user has enrolled, and flags any still active on a disabled or deleted user.

How it handles data

  • Read-only. It only makes requests to the same Okta Privileged Access address you are signed in to.
  • It uses your existing console session. The session token is read when needed and is never stored, logged or sent anywhere else.
  • Explaining policy access needs permission to read security policies, which admin roles have. Without it, the grouped list still works and the access details are hidden.
  • It remembers your chosen grouping in your browser, for that console only.
  • CSV exports contain usernames, server names and access details. Store and share them as you would any access review evidence.

Limits

Access results are worked out from policy data. They are not Okta’s own check. The tool also depends on internal details of the console that Okta does not document and may change, so treat its output as guidance and confirm anything important in the console.
